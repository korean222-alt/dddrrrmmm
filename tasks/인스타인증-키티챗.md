# 작업: 팔로우 인증으로 기능 열기 (키티챗 팔로워 암호)

새 채팅에서 이 파일과 CLAUDE.md, README.md 를 먼저 읽고 시작한다.
처음 계획(2026-11-16)은 "댓글 코드 + 팔로워 암호"였고, **2026-11-17 에 팔로워 암호 방식으로 먼저 만들어 배포했다.** 댓글 코드(본인 확인)는 아직 안 함.
고양이섬(korean222-alt/instaer) `tasks/opus-5-인스타인증-키티챗.md` 와 비슷한 방식. 키티챗 Pro 계정 2개 중 하나를 드럼용으로 쓴다.

## 결론 (왜 이 방식인가)
- 사용자는 **사업자 등록을 할 수 없다** → Meta 앱 심사(고급 권한) 불가 → 아무 유저의 DM 을 받는 웹훅은 못 쓴다. (예전 DM 웹훅·코드 인증은 이 이유로 삭제됨)
- 매니챗 Pro 는 비싸서 제외. **키티챗 Pro ($22/월, 인스타 계정 2개)** 로 결정.
- 키티챗은 외부 API/웹훅을 못 부른다 → 우리 서버는 "누가 팔로워인지" 직접 알 수 없음 → **팔로워에게만 보이는 버튼 DM 속 암호**로 대신한다.

## 지금 동작 (2026-11-17 배포, 운영 중)
### 잠금
- **1~3단계**: 누구나 (맛보기). `charts.js` `FREE_UPTO = 3`.
- **4~14단계 + 💎 무제한(그리그 `endless`, 단계별 `e1`~`e14`)**: 인증 완료한 사람만. `isClosed(id)`, 서버 `/api/runs` 403 `confirm_required`(참여자 없음/아이디만) · `confirm_pending`(아이디만 적고 확인 전).
- 건너뛰는 단계 없음 (`SKIP_LEVELS = []`), 1→14 차례로. 그리그 무제한은 12단계를 깨면.
- `VERIFY_LEVELS`/`needsVerify` 는 예전 '신청만 해도 열림' 단계용 → 이제 비어 있음(호환용으로만 남김).

### 랭킹
- 점수 등록(`/api/scores`)은 인증 완료한 사람만 (403 `verify_required`). `GATE_MODE=open` 이면 예외(개발용).
- 랭킹 조회(단계·총 등수·무제한)도 `checked_at` 있는 사람만 (`store.js` / `pgstore.js` 둘 다).
- 랭킹엔 **닉네임**만 보이고 인스타 아이디는 안 보임.

### 인증 = "인증 완료" = `players.checked_at`
- **팔로워 암호**: `POST /api/verify/password { name?, ig?, password }`
  - 처음 온 사람은 닉네임 + 인스타 아이디 필수, 이미 참여한 사람은 암호만.
  - 맞으면 `setChecked(true)` → 바로 전부 열림. 틀리면 아무것도 저장 안 함(403 `wrong_password`).
  - 띄어쓰기·대소문자 무시(`samePassword`). **틀린 시도만** 세서 IP 당 10분에 10번 → 429.
- **운영자 확인**: `/admin.html` → 인증 신청자 탭 → 확인함 / 랭킹에서 내리기(5일 뒤 삭제) / 삭제. 같은 `checked_at` 을 씀.
- 인스타 아이디를 바꾸면 `checked_at` 이 지워져서 다시 인증해야 함.
- 예전 "아이디만 적고 신청하기" 경로는 화면에서 없앰. `/api/guest` 는 인증한 사람의 닉네임·아이디 바꾸기용으로 남김.

### 팔로워 암호 관리
- 처음 값: Vercel 환경변수 `FOLLOW_PASSWORD` (Sensitive, production). **코드·저장소에 암호를 쓰지 않는다.**
- 교체: `/admin.html` → 인증 신청자 탭 → 🔑 팔로워 암호 (`GET/POST /api/admin/follow-password`). DB `settings`(`set:followPassword`, JSON 저장소는 `settings.followPassword`) 값이 환경변수보다 우선, 빈 값으로 저장하면 환경변수로 돌아감.
- **주 1회 교체**, 바꿀 때 키티챗 DM 문구도 같이 바꾼다.

### 인증 창 (`public/index.html` `#modal-verify`, `main.js` `openVerify`/`submitVerify`)
1. 팔로우하기 → 2. 아무 게시물·릴스에 「쿵」 댓글 → 3. DM 버튼 눌러 팔로워 암호 받기 → 4. 닉네임·아이디·암호 적고 인증하기.
- 잠긴 단계·무제한·랭킹 참여 버튼·1~3단계 끝난 뒤 랭킹 올릴 때 이 창이 뜸.
- DM 링크 `/?k=암호` 로 들어오면 창이 열리고 암호가 미리 채워짐(주소에서는 지움).
- 키워드는 `VERIFY_KEYWORD = '쿵'` — 키티챗 키워드와 같아야 함.

## 키티챗 설정 (사용자가 폰에서 함)
- 자동화 종류: 댓글→DM / 게시물: 전체 / 키워드: 특정 `쿵` / DM→DM 적용: 끔
- '키워드 외에 추가 텍스트가 있어도 자동DM': **켜짐**
- 대댓글: 일반 / 발송: 즉시 / 댓글 모니터링: OFF(Expert 전용)
- DM 종류: **버튼**, '팔로워에게만 버튼 속 메세지 공개' **체크**, AI 적용 **끔**(암호가 바뀔 수 있음)
  - 제목 `🥁 쿵쿵드럼 팔로우 인증` / 버튼 `팔로워 암호 받기`
  - 버튼 속 메시지: `[username]님 팔로우 고마워요! 🥁 / 이번 주 팔로워 암호: (암호) / 👉 https://kongkong-drum.vercel.app/?k=(암호) ` (링크 뒤 공백)
- 비팔로워 메시지: `팔로우 해주셔야 암호가 보여요 💌 팔로우하고 아래 버튼을 다시 눌러주세요!` / 재시도 버튼 `팔로우했어요!`
- 자동 대댓글: 켜짐, 경고 3회 시 끄기 켜기 추천.
- 미확인(써 보면서 확인): 팔로우 후 버튼 다시 누르면 팔로워 메시지가 나오는지 / 문구 수정이 바로 반영되는지 / 여러 번 댓글 달면 DM 이 매번 가는지.

## 알려진 한계
- 암호를 아는 사람이 **남의 인스타 아이디**를 적어도 통과된다(본인 확인 없음). 운영자가 admin 에서 보고 내릴 수 있음.
- 암호가 퍼지면 팔로워가 아니어도 통과 → 주 1회 교체로 줄인다.
