# 채보 만들 때 주의 — 아이폰 터치 빠짐 (2026-11-24)

새 곡·유저 맵 자동 드럼·무제한 패턴을 만들거나 고칠 때 이 파일을 먼저 읽는다.

## 무슨 일인가
- 아이폰(사파리 엔진 WebKit)은 **한 엄지가 화면에서 떨어지는(또는 누른 채 움직이는) 순간**과 **다른 엄지가 닿는 순간**이
  화면 한 틱(0.008~0.016초) 안에 겹치면 둘을 '뗌' 이벤트 하나로 합쳐 보낸다. 닿은 엄지의 touchstart 는 따로 안 만든다.
  - 확인한 것: WebKit 소스 `Source/WebKit/UIProcess/ios/WKTouchEventsGestureRecognizer.mm` `_processTouches`
    (`lastExpectedWKEventTypeForTouches` 가 가장 늦은 단계(뗌)만 보내고 나머지는 건너뜀).
  - 그 뒤 웹 쪽 처리는 애플 비공개 코드. 운영자 폰은 그 손가락이 늦게라도 들어왔고(「살림」 헛침), DM 유저 폰은 아예 사라짐
    → **iOS 버전 차이로 추정(확인 안 됨)**. 터치 표시(`/?touch=show`) 맨 아래 줄에 기종·iOS·브라우저가 나오니 영상으로 확인할 것.
  - 아이폰은 크롬·인스타·카톡·홈 화면 앱 모두 같은 엔진 → 브라우저 바꿔도 같다. 안드로이드는 해당 없음.
  - 폰이 아무 신호도 안 주므로 게임 코드로 그 터치를 살릴 수 없다. **touches 목록으로 터치를 만들어 내지 말 것**(CLAUDE.md 「살림」).
- 엄지를 짧게 톡 튕기는 사람(누르는 시간 0.03~0.07초)일수록 잘 겹친다.

## 언제 잘 터지나 (= 채보에서 피할 것)
1. **쌍(동시치기)**: 두 엄지가 거의 같이 닿고 한쪽이 금방 떨어짐 → 다른 쪽이 0.03~0.06초 늦게 닿으면 겹침.
   DM 영상에선 쌍 5번 중 3번 빠짐.
2. **번갈아 빠르게**: 다른 엄지 콩이 **0.04~0.16초 앞**에 있는 콩 (예: 쿵 → 0.11초 뒤 짝). 앞 엄지가 떨어지는 때와 겹치기 쉽다.
   짝 줄(4줄 곡 왼쪽에서 3번째)이 '잘 안 눌린다'는 신고 = 이게 짝 줄에 제일 많아서 (크리스마스 곡 짝 120개 중 56개).
3. 같은 엄지 연타는 이 버그와는 상관없다(같은 손가락이라 겹칠 수 없음). 다만 그동안 다른 엄지를 누른 채 움직이면 겹칠 수 있음.

**줄 위치(옆 줄이냐, 한 칸 띄우냐)는 주원인이 아니다 — 원인은 시간.** 두 엄지가 붙어서 하나로 합쳐지는 경우도 있긴 하지만
(DM 영상 3번 중 1번) 나머지는 두 엄지가 2~3cm 떨어져 있어도 빠졌다.

## 새 채보 규칙
- 다른 엄지 콩끼리는 되도록 **0.18초 이상** 띄운다 (BPM 160 이하면 8분음표 = 0.1875초 이상).
  - 입문·쉬움·보통: 0.04~0.16초 번갈아 **안 씀**.
  - 어려움·지옥: 써도 되지만 한 번에 길게 이어지지 않게(4개 이하로 끊기), 곡 전체에서 기존 같은 난이도 곡보다 적게.
- 쌍은 **박 머리(정박)에만**, 앞뒤 0.2초 안에 다른 콩 없게. 입문·쉬움엔 거의 안 씀.
  - 쌍은 되도록 바깥 줄끼리(챙+츠, 쿵+츠) — 두 엄지가 붙어 합쳐지는 경우까지 줄임.
- 다 만들면 `node scripts/chart-risk.mjs <단계 번호>` 로 '쌍'·'번갈아' 수를 보고, 같은 난이도 기존 곡보다 낮게 맞춘다.
- **기존 곡 채보는 안 바꿈** — 랭킹 기록이 옛 채보 기준이라 바꾸려면 사용자 결정 + 그 단계 랭킹 처리 필요.

## 게임 쪽 처리 (이미 있음)
- 쌍에서 한 콩을 쳤고, 남은 콩 쪽 엄지 자리에 헛침·늦은 터치·일찍 누름이 없으면 → 남은 콩 **GOOD**
  (game `_canPairSave`·`_pairSave`, 하트·콤보 그대로, 늦게 도착한 진짜 터치가 오면 그 터치로 다시 판정).
  무제한·챌린지(`level.challenge`)·멀티(`pairHeart:false`)는 안 함. 점수 check 에 `ps`(봐준 수) → admin 🕵 자세히 보기 '🖐 쌍 봐줌'.
- 번갈아 빠르게 쪽은 봐주지 않음 (2026-11-24 사용자 '애매하다').
