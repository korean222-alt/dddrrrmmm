# Neon → Cloudflare D1 옮기기 (2026-11-21 결정 · 코드 준비 끝, 데이터 옮기기 대기)

## 왜
- Neon 무료(okaystra, Vercel 통해 만든 Neon 계정, 프로젝트 holy-flower-36131317, 싱가포르)가 못 버팀.
  11/15~11/21 6일에 Compute 33.54 CU-시간(하루 ~5.6, 거의 안 잠듦), 네트워크 전송 2.19GB(하루 ~0.36GB).
  무료 = 월 100 CU-시간 · 전송 5GB → 12월엔 전송 ~14일, Compute ~18일이면 바닥.
- D1 무료: 하루 읽기 500만 줄 · 쓰기 10만 줄 · 5GB, 깨어 있는 시간·전송 한도 없음, 넘어도 다음 날 9시(KST) 풀림.
  Worker 안 쿼리라 '요청당 바깥 연결 50번'에도 안 걸림. 사용자: "한 사이트에서 다 하는게 낫지".

## 준비 끝난 것
- GitHub Actions 의 CLOUDFLARE_API_TOKEN 에 '계정 → D1 → 편집' 권한 추가함 (사용자, 11-21).
  → D1 만들기·데이터 넣기·배포 전부 Actions 로 (이 작업 환경은 wrangler deploy 안 됨, 연결된 Cloudflare 커넥터는 다른 계정일 수 있어 쓰지 말 것).

## 할 일
1. Actions 로 D1 `okaystra` 만들기 (wrangler d1 create) → id 를 wrangler.jsonc d1_databases 바인딩(DB)에.
2. server/d1store.js: pgstore.js 와 같은 메서드, SQLite 문법. 주의: rooms JSONB 연산(patchRoom·findOpenRooms) → json_patch/json_extract,
   DO 블록·BIGINT·FILTER·ROW_NUMBER, schemaBlock 대신 batch. 테스트는 SQLite(예: node:sqlite)로 server.test 등 전부.
3. 데이터 옮기기: Actions 에서 Neon(DATABASE_URL 은 Cloudflare 비밀값 → GitHub 비밀값으로도 필요할 수 있음, 사용자에게 요청) 읽어 D1 에 넣기.
   표: players, scores, season_scores, hall, maps, map_votes, map_scores, suggestions, recover_requests, settings(secret:session 꼭!), sessions, plays.
   rooms·transfers·used_runs 는 안 옮겨도 됨. secret:session 이 같아야 기존 로그인 쿠키 유지.
4. worker/index.js: env.DB 있으면 D1, 없으면 Neon (되돌리기 쉽게).
5. 전환 후 Neon 은 백업으로 남김. 옛 Vercel 다리(api/server.js)는 Neon 을 쓰므로 다리 끝날 때까지 Neon 유지.

## 진행 (2026-11-21)
- 코드 끝: `server/d1store.js`(PgStore 상속, $1→?1 바꿔 대부분 그대로 · cleanup·recordScore·trackPlays(바인딩 100개라 9줄씩)·patchRoom(json_set 얕게 합치기)·pickRankedRuns 만 다시 씀).
  테스트 `test/d1store.test.js`(PGlite 와 결과 비교) · `test/d1sync.test.js`(복사·따라잡기·되돌리기) · `TEST_D1=1` server.test.
- D1 `okaystra` 만듦 (id 3b6401ad-5020-40ea-b03e-82abe5384536, apac) → wrangler.jsonc `DB` 바인딩, 배포됨.
- **어느 DB 를 쓸지 = Cloudflare 비밀값 `DB_MODE`**: `d1` 이면 D1, 없거나 `neon` 이면 Neon. 배포·푸시와 상관없이 유지됨.
  d1 인데 바인딩이 없으면 Neon 으로 넘어가지 않고 503 (두 DB 에 나뉘어 쓰이는 것 막기). `/api/health` 에 `db` 표시.
- D1 모드에서도 옛 Vercel 다리의 '기록 옮기기' 코드는 Neon 에서 한 번 더 찾음(DATABASE_URL 남겨 둘 것).
- Actions 'D1 옮기기'(`.github/workflows/d1-migrate.yml`, step 고르기): prepare / migrate / verify / rollback.
  migrate = 랭킹 적어 두기 → 전체 복사 → 맞춰 보기(줄·내용·secret:session, 안 맞으면 멈춤) → `DB_MODE=d1` → 그 사이 Neon 기록 따라잡기 → 사이트 랭킹 비교 + 예전 쿠키 키로 로그인 확인(실패 시 자동 Neon 복귀).
  rollback = `DB_MODE=neon` → D1 에서 생긴 기록을 Neon 에 합침 → 사이트 확인. 급하면 Cloudflare 대시보드에서 DB_MODE 를 neon 으로만 바꿔도 즉시 Neon.
  스크립트 `scripts/d1-sync.mjs`(D1 REST API) · `scripts/d1-site-check.mjs`. 필요 비밀값: GitHub `NEON_DATABASE_URL`.
- rooms·transfers·used_runs 는 안 옮김(잠깐 쓰는 것).
